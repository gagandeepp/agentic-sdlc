## Plan 4 — M5: Parallel devs (branch `plan-4-parallel-devs`)

### Why this isn't just "run Dev three times"
- **Sessions kill each other.** After *every* session the runner runs `sudo -u agent kill -KILL -1` (`api/app/agents/isolation.py:14-20`, called at `runner.py:271-274`). Concurrent sessions on the one `agent` uid would kill each other.
- **The network-git guard blocks pushes.** It refuses clone, fetch and push while `pgrep -u agent` finds anything (`gitops/repo.py:86-94`).
- **Shared HOME.** `api/docker/agent-cli` gives every session `HOME=/work/agent-home`.
- **Branch names [B1].** The spec's `sdlc/<run>/task-<id>` can't exist next to the branch `sdlc/<run>`; git's ref layout forbids it. Task branches become **`sdlc/<run>-task-<id>`** (update the spec and `fake_run.py`).
- **Unvalidated task ids [B2].** Architect task ids end up in paths, refs and commits, but nothing validates them (`agents/artifacts.py:29-35`).
- **A shared-state assumption breaks under concurrency in four places:**
  - `GateBroker` silently overwrites a second open gate (`gates.py:66`).
  - Overlapping `ActiveClock.paused()` calls from different tasks restart the clock too early.
  - `ArtifactStore.save` races on `latest+1` (`store/artifacts.py:65-79`).
  - Devs would share `claude/dev`.
- **Budget under concurrency [I1].** The proxy marks the budget permanently exhausted when a pre-request *reservation* fails (`llm/registry.py:35-39`). Three devs' reservations can cross the cap while actual spend is still low.

### Decisions
1. **Agent uid pool**:
   - **Users:** `agent-1..agent-4` (3 devs + Integrator headroom). `Settings.agent_users` comes from `AGENT_USERS=agent-1,…` (names validated, no duplicates). It replaces `agent_user`; an empty pool means Bash roles refuse, so it fails closed.
   - **Leasing:** `AgentUidPool` in `isolation.py` is owned by `SdkAgentRunner`, so the probe uses it too. `lease()` waits for a free uid and kills its leftover processes on acquire. On release it kills them again, and the uid returns to the pool only after that kill finishes [I5].
   - **CLI wrapper and sudoers:** the runner passes `AGENT_USER` in the session env. `agent-cli` requires and validates it, and never passes it on to the agent. Each uid gets its own HOME, `/work/agent-home/<user>` (0700) [I6]. sudoers gets `Runas_Alias AGENTS = agent-1, …`.
   - **Network guard:** checks every pool uid.
   - **`max_concurrent_runs`:** stays pinned at 1, with an updated reason comment.
2. **Task worktrees attached to the API-owned git dir:**
   - Created with `git worktree add -b sdlc/<run>-task-<id> runs/<id>/worktrees/task-<id> <run-head>`. `worktrees/` is API-owned (2750).
   - Task `RunRepo`s bind `GIT_DIR=<gitdir>/worktrees/task-<id>`, so a `.git` file an agent plants is ignored.
   - `lock_down(common_dir)` runs after every write [I3].
   - The git dir gets an `info/attributes` file with `* merge=text conflict-marker-size=7`. Agent-planted `.gitattributes` then can't hide conflicts (`merge=union`) or defeat the marker scan [I4].
   - `_HARDENING` adds `gc.auto=0` and `maintenance.auto=false`. `read_inside` gets FIFO-safe like `write_inside`.
3. **Scheduler** (pure module, `orchestrator/scheduler.py`):
   - **Edges:** `depends_on` plus file-overlap edges. Overlap means the same path or a directory/glob prefix; a task with no files listed is serialized against everything.
   - **Edge direction:** overlap edges follow a stable topological order of `depends_on`, so a forward dependency can't create a cycle [B3].
   - **Output:** waves = longest-path levels. The merge order is the stable topological order.
   - **Validation [B2]:** done earlier, by the `Design` model:
     - ids must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,23}$`;
     - no duplicate ids;
     - no unknown or self dependencies;
     - no cycles;
     - at most 10 tasks.
     A failure becomes `invalid_output`, then the Architect escalation already in place.
   - **Edited designs [I2]:** if the design was edited at the gate, the tasks are parsed back from the edited markdown's `## Tasks` section (round-trip tested). If that fails, the build is one task covering the whole edited design. Stale data is never used.
4. **Waves, not merge-as-you-go.** Each wave runs its tasks concurrently, as agents `dev-1..dev-N` (by slot, with `task_id` in `agent.started`). It then drains, then integrates. This keeps three rules simple:
   - The API only runs git commands that write when no agent is alive.
   - Gates open only between waves (one at a time; the clock assumptions hold).
   - The merge order is deterministic.
5. **Integration** (per wave, `Phase.INTEGRATE`):
   - **Before merging:** `reset_clean` the run tree. Anything an agent wrote there through Bash is discarded, with a `guardrail.blocked(stray-run-tree-changes)` event [I7].
   - **Each task branch:** `merge --no-ff`, with `merge.started`, `merge.conflict` and `merge.completed` events (which gain `task_id`).
   - **On conflict:** the Integrator agent (Sonnet; Read/Edit/Write/Glob/Grep plus `git diff/log/show/status`) works on the run tree. The API then scans for leftover markers, never following symlinks. It concludes with `conclude_merge()`, which always commits while MERGE_HEAD exists, even if the result equals HEAD [B4]. The run saves an `IntegrationResult{resolved_files, notes}` artifact.
   - **Commit and merge messages** contain only API text and the validated task id [I8].
6. **Failures:**
   - **A failed dev task:** the other sessions drain first. Then escalation gates open one at a time (approve = retry, revise = retry with guidance, abort). The failed tasks retry in their existing trees.
   - **A task that changed nothing:** recorded, not escalated. If the whole build changed nothing, the M4 escalation runs and falls back to the single-dev `_develop`.
   - **Integrator failure or leftover markers:** an escalation gate.
   - **Budget exhausted** in any session: the siblings are cancelled, then `run.failed(budget)`.
   - **[B5]** One helper unwraps TaskGroup `ExceptionGroup`s: cancellation first, then the budget stop, then the first error. Abort, shutdown and timeout therefore still end the run correctly.
   - **The concurrency fixes become enforced rules:** `GateBroker.wait` raises if a gate is already open; `paused()` counts depth; `ArtifactStore.save` takes a lock per run; DevResults are saved in task order after the drain.
7. **Budget [I1]:**
   - `try_reserve` returns `ok`, `busy` or `exhausted`. If it falls short only because of other requests in flight, the proxy answers **429 + `retry-after`**, which the CLI retries.
   - Only a request that can't fit on its own makes the budget exhausted (400, as today).
   - The SDK `max_budget_usd` = budget − spent, ignoring the other sessions' reservations.
8. **One code path.**
   - **Initial builds:** every one goes through the scheduler; one task means one wave and one merge.
   - **Fixes:** review, QA and release-revise fixes stay as one `dev-1` session on the run tree, as in M4.
   - **Config dirs:** one per agent, `claude/<agent_id>`.
   - **Handoffs:** architect→dev-k (wave 1), integrator→dev-k (later waves), dev-k→integrator, integrator→reviewer.
   - **Phases:** `phase.started`/`phase.completed` for dev and for integrate, once per wave, with attempt counters.
9. **Resume is unchanged.**
   - A resume before `pushed` re-clones the base, discards `worktrees/` (rename-then-delete, because agent files can't always be removed [I9]) and re-runs every wave.
   - No checkpoint per wave: it would push half-built code and trigger CI.
10. **Contracts:**
    - `DevResult.task_ids` stays; the spec table is corrected.
    - New: `IntegrationResult`, with `render_markdown`.
    - New: `config/agents/integrator.yaml` and `prompts/integrator.md`, which include the shared rules paragraph.
    - New prompt builders: `task_prompt(...)` and `integrator_prompt(...)` in `orchestrator/prompts.py`.
    - `dev.md` gets a per-task mode. `architect.md` covers the id format, dependency order, and listing shared files such as README and lockfiles explicitly.
    - Regenerate the TS types and the fixture.
11. **Keyless demo:**
    - `ScriptedAgentRunner` scripts can be keyed by `(Role, task_id)`. A default scripted Integrator strips the markers and keeps both sides.
    - `demo_script()` for `POST /api/dev/scripted-runs`: T1 and T2 run in parallel and both append to an undeclared README, so the Integrator runs; T3 depends on T1.
    - `DEFAULT_OUTPUTS` stays one task, so the M4 tests keep their meaning.
12. **API and GUI:**
    - `StartRunRequest.max_parallel_devs` (default 3, at least 1). Above `Settings.max_parallel_devs` the API returns 400.
    - The manager passes it through; the hard-coded 1 at `manager.py:103,116` goes away.
    - `NewRunForm` gets a "Max devs" select (1–3). Everything else in the GUI waits for M6.

### Key tests (scripted, real temp git repos, testcontainers Mongo)
- **Scheduling:** two independent tasks overlap in time (both `agent.started` before either `agent.finished`). The merge order is deterministic.
- **Conflicts:** an undeclared README overlap runs the Integrator and saves the integration artifact. Leftover markers escalate, then a retry succeeds. A resolution identical to HEAD still clears MERGE_HEAD.
- **Planted `.gitattributes`:** a planted `.gitattributes` with `merge=union` or an undefined driver still conflicts and executes nothing. A hook in a swapped `.git` inside a task tree never runs.
- **Failure paths:**
  - **Failed task:** a failed task drains its wave, then escalates and retries.
  - **Budget:** budget exhaustion cancels the siblings and ends `run.failed(budget)`, with no gate.
  - **Abort and timeout:** abort or timeout in the middle of a wave ends correctly, and the uid pool is fully released.
  - **Interrupt:** an interrupt in wave 2 followed by resume re-runs every wave.
- **Edges:**
  - A stray file an agent writes into the run tree is discarded.
  - `.github` changes merged from task branches are still refused at push.
  - `sdlc/r` and `sdlc/r-task-T1` coexist.
- **Uid pool:** different uids for concurrent leases, a waiter blocks, the kill runs on acquire and on release, and a cancel during release still kills before the uid is returned.
- **Existing tests that change:**

## Plan 5 — M6: GUI polish (branch `plan-5-gui`, written after Plan 4 merges)

### Problems found in today's GUI that shape the design
- **The event log costs O(n²).** The reducer copies the whole timeline on every event (`web/src/store/reducer.ts:113`). `RunPage` subscribes to the entire state and rescans the log on every batch (`RunPage.tsx:16-27`).
- **Usage arrives per API request.** Live `agent.usage` comes once per API request (`api/app/llm/sink.py`), so Haiku side calls overwrite `contextTokens` and the bar jumps. `turns` counts usage events, not SDK turns.
- **Spend comes from two places.** It's summed from usage, then overwritten by `budget.updated`, so with parallel devs it can briefly go down.
- **Handoffs are irregular.** Live handoffs come before each session, from `"orchestrator"`, with no `agent_id`. The fixture's come after gates. M4's dev is `dev`; M5's are `dev-k`.
- **Fixture artifacts are never stored**, so the gate panel and artifacts list fail for fake runs and replays.
- **The web build can't read `fixtures/`** (Docker context `./web`, Vercel root `web/`).
- **The backend lacks:** per-role rollups, `/api/compare`, and list filters or a cursor (`api/app/api/runs.py:132-136`).

### Decisions
1. **No further event-contract changes** beyond M5's `task_id` on merge events, which maps merges to dev nodes. Backend additions are only:
   - `RunSummary`;
   - an optional `RunRecord.summary`;
   - `GET /api/compare?ids=`;
   - a demo manifest model.
2. **Summaries are computed on the server.**
   - **What it is:** a pure `summarize(events) -> RunSummary` in `api/app/store/summary.py`. It covers cost, tokens and sessions by role; wall, active and gate-wait time; loop counts; cache-hit ratio; gates; merges and conflicts; guardrail blocks.
   - **When it's computed:** on read, when it's missing or stale (`summary.last_seq < run.last_seq`, or an old version), then saved.
   - **Consistency:** a cross-language golden test makes the Python summary and the TS reducer agree.
   - **Endpoints:**
     - `GET /api/runs?limit&before&mode&status`;
     - `GET /api/compare?ids=a,b`: 2–4 distinct ids, returned in the requested order.
3. **The event log leaves the reducer.**
   - The store keeps an append-only `log` and a `count`. The pure reducer adds:
     - a per-agent request series (context taken only from the agent's own model);
     - handoffs and edge counts;
     - loop counters;
     - phase, gate, merge and artifact history;
     - start and end times;
     - separate `costUsd` and `spentUsd`;
     - `graphVersion`.
   - **`waiting` status:** set when an agent's artifact is at an open gate, or when it's a queued handoff target.
   - **Rename:** the web `TokenTotals` becomes `TokenCounts`.
4. **Replay player:**
   - **Controller:** rAF-driven, with an injectable clock. Speeds 1/2/4/8/16×; gaps between events are capped at 2 s, and gate waits at 1.5 s.
   - **Seeking:** snapshots every 250 events.
   - **Animation:** handoffs animate only for `seq > animateAfterSeq`, so seeks and live catch-up never fire old packets.
   - **Routes:** `/runs/:id` (live), `/runs/:id/replay` (`events.jsonl`) and `/demo/:slug` (static bundle). All three render one `MissionControl` page; replay is read-only.
5. **Featured demos are static files:** `web/public/demos/{index.json,<slug>.jsonl,<slug>.artifacts.json,<slug>.summary.json}`.
   - **Source:** written by `app.dev.export_fixture`, which also saves real artifacts for fake runs. Pytest checks they're fresh.
   - **Scenarios:** `fake-basic`, plus a `fake-conflict` scenario (QA loop, Integrator conflict, escalation, guardrails at INIT).
   - **Later:** M7 adds recorded runs to the same manifest.
6. **Graph** (`@xyflow/react`, fixed lanes, no layout library):
   - **Lanes:** orchestrator/guardrails → BA → Architect → dev-1..N stacked → Integrator → Reviewer → QA → DevOps → PR.
   - **Edges:** `flow`, `skip` and `loop` kinds. Loop edges show "↺ n/limit"; the revise loop is shown as a node badge.
   - **Packet:** an SVG `animateMotion` started with `beginElement()`. Under reduced motion it becomes a highlight.
   - **Nodes:** accessible buttons that open the inspector. A Graph/List toggle keeps the agent cards.
7. **Charts follow the dataviz skill:**
   - **Palette:** a CSS-variable palette (`--chart-1..8`) that works in both themes.
   - **Cost vs budget:** a **meter** (warning at 75% and critical at 90%, each shown with an icon and a label).
   - **Small charts:** the meter and sparkline are hand-written SVG.
   - **Recharts:** lazy-loaded, used only in the inspector and the compare page.
   - **Tables:** every chart has a Table view.
8. **Theme:**
   - **Mechanism:** Tailwind v4 `@custom-variant dark` and `@theme inline`, with shadcn variable names.
   - **Toggle:** saved in localStorage, dark by default.
   - **No flash:** a script in `index.html` sets the theme before first paint.
9. **shadcn/ui, minimal:** Button, Sheet, Tabs, Slider, Tooltip, ToggleGroup and Badge, vendored into `src/components/ui` with an `@/*` path alias.
10. **Markdown and diffs:**

    - **Diffs:** a hand-written unified-diff colorizer, plus a capped line diff for Edit calls.

11. **Playwright:**

## Review focus (for each plan's final Opus review)
- **M5 isolation:**
  - A uid is never leased twice, and goes back to the pool only after its kill has finished.
  - The kill hits only the leased uid. The network guard covers the whole pool.
  - sudoers can switch only to pool users, and `AGENT_USER` never reaches the agent.
- **M5 git:**
  - Every git call binds `GIT_DIR`; only `clone` doesn't.
  - Merges execute nothing from the repo.
  - Git commands that write run only when no agent is alive.
  - MERGE_HEAD is never left behind.
  - The conflict scan doesn't follow symlinks and doesn't block.
- **M5 control flow:**
  - Exactly one gate is open per run at a time.
  - Exactly one terminal event per run; cancellation beats child errors.
  - Budget exhaustion is never misreported as an error.
  - The task graph never comes from stale design data.
- **M6:**
  - Replay totals = Python summary = fixture sums.
  - Cost stays linear in events; seeking backwards = a fresh reduce.
  - Markdown safety.
  - Replay never sends a POST.
  - Accessibility: status has an icon and a label, every chart has a table, the drawer handles focus, reduced motion is respected.
  - Demo copies and generated types are checked for freshness.
